Execution Flow

What actually happens between pressing Enter and seeing a whale of an answer.

1

index.tsx boots

Loads config (defaults ← file ← env ← CLI), enforces the root/sudo safety gate, branches to headless --print if requested, then renders <App>.

2

App.tsx takes the wheel

Manages runtime state — model, agent, messages, thinking blocks, effort, permissions, overlays.

3

Message submitted → native Agent + Session

getOrCreateMemorySession() builds the engine: model + tools + instructions + providerOptions. The C++ session owns the whole agentic loop — history, memory auto-inject, sliding-window compaction, retries, max-steps. The cache key includes effort, so changing effort rebuilds the session.

4

Events stream back through query.ts

Native StreamEvents (text, reasoning deltas, tool calls, step finish, finish, error) get mapped to UI QueryEvents. Do not reimplement the loop in TS — the docs are very firm about this.

5

processAgentStream() renders

Consumes events, keeps refs as the source of truth, and batches state updates into ~80ms flushes for smooth Ink painting. Text, thinking and tool blocks accumulate chronologically; on step finish they finalize into history.

6

Tools run through the permission pipeline

Rules engine consulted first (global deny hard-blocks, global allow auto-approves), then per-tool checkPermissions(), then the interactive <PermissionPrompt> with diff preview. Plan mode denies write/execute tools. Your Tab feedback lands in the tool result as 💬 User note.

Key Patterns

The decisions that make this thing work.

⚙️Native engine, thin TS skin

The C++ ai-sdk-cpp session owns the agentic loop: history, memory auto-inject, sliding-window compaction, retries, max-steps. TS only maps events to UI.

session.sendStream() → StreamEvents
        ↓
query.ts → QueryEvent → Ink renderer

🔀Config merging

Priority: CLI args > persisted settings > env > .deepseek-code.json > defaults. Files support env:VAR references, and legacy .zcode.json paths still work — backwards compatibility matters.

🛡️Permission engine

Tool(spec:pattern) allow/deny/ask rules run before prompting. Global deny hard-blocks; global allow auto-approves; otherwise the interactive prompt with diff preview.

Bash(npm test:*)
FileWrite(path:src/**)

🧠Reasoning effort

--effort off|low|medium|high|max flows into providerOptions.openai.reasoningEffort. It's part of the session cache key — changing it rebuilds the session. StatusBar shows ○/◐/●/◉.

⚡80ms batched streaming

Refs are the source of truth; state updates flush in ~80ms batches with dirty flags to skip redundant setState. incrementalRendering stays off — full erase+redraw avoids input-refresh desyncs.

🎨Frontend port

Claude Code's UI ported onto stock Ink — getTheme() → Theme (dark/light/ansi), resolveColor() for ansi: tokens, ThemeProvider resolves 'auto' via $COLORFGBG. No fork-ink imports, ever.

📚Skills system

SKILL.md discovered from project .claude/skills/, user ~/.claude/skills/, and bundled src/skills/bundled/ (project > user > bundled). SkillTool embeds the listing in its description; bun run build copies bundled skills to dist.

💸Recovery & cost tracking

413/prompt-too-long → advise /compact; 429 overload → one-shot retry on a fallback model, never more than once per turn. TokenTracker estimates cost with DeepSeek pricing and cache-hit discounts.

🧩Three agents

code — full read+write+execute, 25 steps. plan — read-only, 15 steps. review — read-only, 15 steps. Defined in services/agent/index.ts.

🔌Hooks & plugins

User-configured shell hooks: PreToolUse (blocks via exit code 2 or JSON decision), PostToolUse, UserPromptSubmit, Stop, Notification — fire-and-forget, config in ~/.deepseek-code/settings.json.
