# Feature Gaps: DeepSeek Code vs Claude Code

Generated by a multi-agent workflow that mapped **608 features** in the reference
Claude Code source (`~/Downloads/claude-code-main/src`) and **196 features** in
DeepSeek Code (`~/deepseek-code/src`), then diffed them. Result: **79 consolidated
gaps** (10 high, 54 medium, 15 low). One gap agent hit a rate limit, so the long
tail may be ~5% under-counted.

`effort` is rough, against DeepSeek's stack (Bun + Ink + Vercel AI SDK + DeepSeek API).

## 🔴 High priority — core capabilities most coding-agent users expect

### Engine / core loop

- **Headless / print mode + global CLI options** *(engine, large)* — `cli/print.ts`, `main.tsx`
  Non-interactive single-query execution for scripting/CI: `--print`/`-p` runs one prompt and exits; `--output-format text|json|stream-json`; plus `--system-prompt-file`, `--allowed-tools`, `--max-turns`, `--add-dir`, `-n/--name`, `--continue`.
  *Build `src/cli/print.ts` reusing the existing `query()` AsyncGenerator + ContextManager + TokenTracker; extend `parseCliArgs`; add an argv branch in `index.tsx` that runs one prompt and prints JSON without rendering Ink.*

- **Reactive compaction / prompt-too-long (413) recovery** *(engine, large)* — `query.ts`
  Catches prompt-too-long / oversized errors and recovers by compacting then retrying, avoiding death-spirals where an overflowing context never recovers.
  *`ContextManager.compact()` exists; catch the oversized error event in `query.ts`, compact, re-issue once with a loop guard.*

- **Model fallback on overload** *(engine, large)* — `query.ts`
  On provider overload, auto-switch to a configured fallback model and retry once.
  *TS wrapper around `query()` that detects overload, calls `createModel` with a `fallback` profile, recreates the session, re-issues.*

- **Modular dynamic system-prompt builder** *(engine, medium)* — `constants/prompts.ts`
  Assembles the system prompt from OS/platform/git-branch/cwd/date + active tool list + output style + discovered skills, instead of a static string.
  *`services/agent/index.ts` uses static template literals. Build `assembleSystemPrompt({os,cwd,gitBranch,date,tools,outputStyle,skills,model})`.*

- **Permission rule engine** *(engine, large)* — `utils/permissions`, `components/permissions/rules/`
  `Tool(spec:pattern)` allow/deny/ask rule language (e.g. `Bash(git push:*)`, `Read(./src/**)`), with path scoping, denial tracking, shadowed-rule detection, explainer text, and a `/permissions` editor.
  *DeepSeek already declares `permissions?: {allow,deny,ask}` in `storage.ts:47` but **never consumes it** (verified). Parse rules in `src/services/permissions.ts`, glob-match with `fuzzy.ts`, run as the first check in the `tools.ts` execute wrapper.*

### Tools

- **FileRead: image / PDF / notebook reading + binary detection + device-file blocking** *(tools, large)* — `FileReadTool/`, `limits.ts`
  Decode images (token-budgeted), extract PDF pages, read notebooks, block `/dev/*` `/proc/*`, detect binary files by extension+null-byte and return a "binary file, N bytes" summary.
  *No image/PDF/binary code exists (verified). Image support is highest value (DeepSeek's model takes image inputs — use `sharp` or a WASM decoder). Binary detection is small; device-file block is a one-liner.*
  ⚠️ **The FileRead *prompt* already claims image/PDF support** (`prompt.ts:13-14`) — it overpromises an unimplemented capability.

### Tasks / execution

- **Background task framework + `run_in_background` + TaskOutput/TaskStop + `/tasks`** *(tasks, large)* — `Task.ts`, `utils/task/framework.ts`, `tasks/LocalShellTask/`, `tools/TaskOutputTool`, `tools/TaskStopTool`
  Polymorphic Task abstraction + typed lifecycle, a task registry, detached shell tasks with kill support, and tools to read/kill them.
  *Don't confuse with the existing `TaskStore` (that's the TODO list). `BashTool` has no `run_in_background` param (verified — though its **prompt claims it does**, `BashTool/prompt.ts:22`). Build `Task.ts` state machine → registry → extend BashTool → TaskOutput/TaskStop tools.*

### Infra / safety

- **File-history snapshots (restore files on `/rewind`)** *(infra, medium)* — `utils/fileHistory.ts`, `components/MessageSelector.tsx`
  Snapshots real file contents per turn so rewind/undo restores on-disk files, not just truncates the conversation.
  *`/rewind` (App.tsx) only truncates messages today. Snapshot changed files keyed by message index; restore via FileWrite.*

- **Bypass-permissions safety gate** *(infra, small)* ⚡ — `setup.ts`
  Refuses to run as root/sudo outside a sandbox when `bypassPermissions` / `--dangerously-skip-permissions` is on.
  *DeepSeek has bypass mode but **no root/sudo check** (verified — zero `getuid`/`sudo` refs). Trivial: in `index.tsx`, `if (bypass && process.getuid?.()===0 && !inContainer) exit(error)`. Real security footgun.*

### Extensibility

- **Skills system: model-invocable SkillTool + SKILL.md discovery + `/skills`** *(extensibility, large)* — `tools/SkillTool/`, `skills/loadSkillsDir.ts`, `skills/bundledSkills.ts`
  First-class skills the *model* autonomously discovers and invokes; rich `SKILL.md` frontmatter; bundled defaults; slash surface.
  *DeepSeek has only markdown slash commands (`customCommands.ts`) + plugin prompt templates — neither is model-invokable. Build `src/skills/` + a SkillTool whose description embeds discovered skills.*

## ⚠️ Notable finding: overpromising tool prompts

Several DeepSeek tool prompts are copied verbatim from Claude Code and advertise
capabilities that are **not implemented**. The model reads these and may attempt
to use them, then fail. Recommend either implementing or stripping the claims:

- `FileReadTool/prompt.ts:13-14` — claims image (PNG/JPG) + PDF reading. No implementation.
- `BashTool/prompt.ts:22` — claims a `run_in_background` parameter. Not implemented.

## Suggested sequencing

1. **Safety/cheap first:** bypass root/sudo gate, strip overpromising prompt claims, Zod config validation.
2. **Highest user value:** headless `--print`/`--output-format`, FileRead image/binary, background tasks (`run_in_background`), permission rule engine.
3. **Grounding:** dynamic system-prompt builder (unblocks output-styles + skills), reactive compaction/413 recovery, model fallback.
4. **Ecosystem:** skills system, MCP server entrypoint, memory/memdir, LSP.
5. **Polish:** quick wins above, then medium UI items.
